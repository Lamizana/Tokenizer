Audit & fondations
Revue + choix

Analyser l'existant et poser les choix techniques avant toute modification.

  • Revoir code/token.sol : conflit entre uint8 public constant decimals et le getter decimals() d'OpenZeppelin
  • Vérifier la logique mint / burn / transferOwnership et le total supply
  • Choisir la norme : BEP-20 sur la BNB Smart Chain (réseau partenaire du sujet)
  • Outil de déploiement : Remix IDE + extension BNB Chain
  • Créer un compte sur BSCScan et récupérer des TBNB gratuits via le faucet
2
Smart contract (token "42")
Développement

Corriger et renommer le contrat. Le nom du token doit contenir 42.

  • Nom proposé : Token42, symbole/ticker : T42 (à valider)
  • Corriger le conflit decimals (supprimer la constante, hériter du getter ERC20)
  • Garder : mint (onlyOwner), burn, transferOwnership, events Mint/Burn
  • Commenter le code en français avec des noms explicites (revue à l'évaluation)
  • Vérifier le total supply (ex: 1 000 000 × 1018)
3
Tests & sécurité
Validation

Tester toutes les fonctions sur la VM Remix avant déploiement public.

  • Compiler sur la VM de Remix (machine virtuelle injectée)
  • Tester : deploy, transfer, approve + transferFrom, balanceOf
  • Tester : mint (par owner ✅ / par autre adresse ❌ via onlyOwner)
  • Tester : burn et transferOwnership, vérifier les events
  • Revue de sécurité : propriété, privilèges, aucun fonds réel engagé
4
Déploiement sur BSC Testnet
Deployment

Préparer le dossier deployment/ (obligatoire dans le sujet) puis déployer.

  • Créer le dossier deployment/ à la racine du dépôt
  • Y placer : script Remix, metadata du déploiement, ABI
  • Connecter MetaMask à la BSC Testnet et ajouter les TBNB du faucet
  • Déployer via Remix (environnement « Injected Provider »)
  • Noter l'adresse du contrat et le réseau (BSC Testnet)
5
Vérification & publication
BSCScan

Rendre le contrat vérifié et public sur l'explorateur de blocs.

  • Vérifier le contrat sur BSCScan (source + version Solidity + licence)
  • Définir le ticker T42 et uploader un logo si possible
  • Effectuer des transactions de démonstration (mint, transfer)
  • Indiquer l'adresse du contrat + le réseau dans le dépôt Git (README)
6
Documentation
Documentation

Terminer la documentation du dossier documentation/ et le README racine.

  • Compléter etherscan.md (actuellement inachevé : phrase coupée)
  • Rédiger le README.md racine : choix techniques, norme, réseau, adresse du contrat
  • Documenter comment utiliser le token (install, deploy, transactions)
  • Optionnel
  • Rédiger un whitepaper présentant les caractéristiques du token
  • Créer une vidéo de démonstration (simple lien suffit)
7
Bonus — Multisig
Optionnel

Partie bonus : sécuriser les opérations sensibles avec un système de signatures multiples.

  • Évaluer l'architecture : contrat multisig séparé ou intégré au token
  • Définir le nombre de signatures requises (ex: 2/3) et les signataires
  • Relier le multisig aux actions privilégiées du token (mint, transferOwnership)
  • Tester les scénarios : exécution seulement avec N signatures
8
Livraison finale
Validation

Relecture complète et mise à jour du dépôt avant soumission à l'évaluation.

  • Vérifier la structure attendue : README.md, code/, deployment/, documentation/
  • Démo vidéo optionnelle avec lien dans le dépôt
  • Relecture du contrat et des commentaires (revue de code à l'évaluation)
  • Commit final et push sur Git (partage possible via le compte personnel)
  • Checklist du sujet complète : nom avec 42 ✅, pas de termes insultants ✅
